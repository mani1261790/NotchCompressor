# 画面内容の圧縮比較 — 2026-11-25

## 素材と測定範囲

ユーザーの動画提出は不要。`scripts/make-quality-fixture.py`で独自に生成した1920×1080・60fps・12秒の素材を使用。日本語／英語の10〜32px文字、色文字、1〜2px線、スクロール、動く図形、毎秒の点滅とビープを含む。元動画は25,639,320 bytes。H.264 VideoToolboxの40 Mbps指定とAAC 192 kbpsで作成した**非可逆素材**であり、画面収録そのものではない。生成前PNGを原本動画の画質と取り違えない。

このMac（arm64、macOS 27.3）、同梱FFmpeg 9.0.1で6方式×3回を固定シードで順序を混ぜて比較した。電源・温度・他プロセス負荷は記録していないため、短時間の同一セッション内の参考値として扱う。全方式ハードウェア必須、元fps維持、音声コピー。ビットレート方式は7,464,960 bps指定。総時間には入力解析・圧縮・出力解析・全体デコード検証・音声パケット照合を含め、素材コピーと整合性ハッシュ計算は除く。アプリ全体の所要時間ではない。

## 測定結果（3回の中央値）

| 方式 | 出力 MB（10進） | 削減率 | 総時間 秒 |
|---|---:|---:|---:|
| hevc-bitrate | 10.84 | 57.7% | 5.29 |
| hevc-fast | 11.44 | 55.4% | 3.90 |
| h264-bitrate | 11.18 | 56.4% | 4.77 |
| hevc-quality-50 | 4.07 | 84.1% | 4.95 |
| hevc-quality-65 | 6.35 | 75.3% | 5.14 |
| hevc-quality-80 | 9.90 | 61.4% | 5.38 |

18回すべてデコード検証成功。音声パケットのハッシュとPTSが入力に一致し、比較後も元動画のSHA-256は一致。各方式の1回目について、映像720フレームすべての表示時刻も入力に完全一致した。これは相対的なタイミング保持の証拠であり、耳と目による同期確認の代わりとはしない。

## 画像の確認と暫定判断

各方式の1回目をデコードし、1.0秒の静止文字・細線、4.5秒と10.5秒のスクロール文字を、拡縮しない同座標の切り抜きで比較した。画像抽出は開発用Homebrew FFmpegを使用（同梱版にはPNGエンコーダがない）。

- 品質50: 小さい黒文字と色文字の輪郭ににじみ・周辺ノイズが見え、スクロール中の色文字も劣化。容量だけを根拠に既定採用しない。
- 品質65: 品質50より輪郭が改善。ただし小さい文字や細線周辺には差が残る。容量重視の追加候補として継続評価。
- 品質80、現行HEVCビットレート、速度優先、H.264ビットレート: 確認した切り抜きでは文字を読める状態を保つ。全場面・全動画で同品質という判定ではない。
- 速度優先は現行HEVC比で総時間約26%短縮、出力約5.5%増。この素材での結果であり、画質同等や常時高速を保証しない。

既定は現行HEVCハードウェア／標準を維持する。今回の静止比較だけでは、品質指定や速度優先への既定変更を正当化しない。現行方式が最適という結論でもない。
