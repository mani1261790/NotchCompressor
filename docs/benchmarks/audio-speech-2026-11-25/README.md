# 日本語の合成音声によるAAC再圧縮の確認

2026-11-25。自作映像にmacOSのEddy日本語音声で生成した読み上げを重ねたローカル評価素材。マイク収録・会話・音楽の代表性はない。話者の自然な息遣い、雑音、複数人、低い録音レベル等の品質を保証しない。生成された音声・動画はGitへ登録せず、このMac内に保持する。

元の音声は48kHzステレオ。0秒で左、1秒で右に880Hzの100msの目印、その後2秒から日本語の読み上げを左右同じ信号で収録。PCMの長さ17.937375秒。AAC 256kbps指定で元動画を作成したが、実測の音声ビットレートは188.4kbpsであり元も非可逆。映像は先行の1080p60自作素材を繰り返してコピーした。原稿と声・速度は`fixture-manifest.json`に保存。

## 結果

アプリの音声ビットレート計算に合わせて128／96／64kbpsを指定し、映像をコピー。配布版FFmpeg 9.0.1で変換と全体デコード検証、開発用FFmpeg 7.1.1でPCMへ変換して信号を比較した。各設定の単回の機能確認であり、時間の性能比較ではない。

元動画37.43MBに対する結果（MBは10進）:

| 設定 | 指定kbps | 実測音声kbps | 出力MB | 動画全体の削減率 |
|---|---:|---:|---:|---:|
| 品質優先 | 128 | 96.9 | 37.22 | 0.55% |
| 標準 | 96 | 76.0 | 37.17 | 0.67% |
| 容量優先 | 64 | 54.7 | 37.13 | 0.80% |

3設定とも、全映像パケットのハッシュ・PTS・DTS、音声チャンネル数を保持。コンテナの長さの差は50ms未満、入力ハッシュも不変だった。目印の左右RMSでは各側を保持し、左の信号を右へ入れ替える等の変化は観測しなかった。読み上げ部分は左右同一なので、複雑なステレオ音場の評価には使わない。

元の20ms区間のRMSが0.01より大きいのに、出力が0.001未満になる区間を「大きな欠落」として検査し、該当0だった。これは聴感や単語の聞き取りの合格基準ではなく、全体・区間の消音を拾う補助検査。音声を6〜7秒だけ消した負例では、6.02〜6.72秒の36区間を検出した。元が静かな区間はこの検出に含まれない。

音声だけを圧縮しても、映像が大半を占めるこの素材では動画全体の削減は1%未満。数値だけで容量優先へ変更しない。現行設定を維持し、全設定の聴取は未完了として残す。再圧縮音声のSNRやRMSを、可読性・聞き取りやすさの代用にしない。

## 再現

```sh
python3 scripts/make-audio-quality-fixture.py --video .local-work/quality-fixture/screen-content.mov --output .local-work/audio-fixture
PYTHONDONTWRITEBYTECODE=1 python3 scripts/compare-audio-presets.py .local-work/audio-fixture/source.mov --output .local-work/audio-comparison
```

生成スクリプトにはmacOSのEddy日本語音声、配布版FFmpeg、開発用FFmpegが必要。比較入力は1映像＋1音声（モノ／ステレオ）、120秒以下のサンプルを使う。入力を複製して処理し、同じフォルダーや元ファイルを上書きしない。

今回の素材は`.local-work/next/audio-quality/`、完全な20ms RMS列を含む測定値は`.local-work/next/audio-quality-final/`、消音負例は`.local-work/next/audio-quality-comparison/negative-check.json`。公開したJSONはRMS列を除いた要約で、聴感の判定は含まない。
