# 圧縮速度の検証（2026-11-24、#28）

映像エンコードは既存実装から `hevc_videotoolbox -allow_sw 0` を使い、ハードウェアを必須としている。デコード・音声変換・フィルタ・出力検証まで全部をGPUで実行する構成ではない。

## 比較条件

Apple M2、同梱FFmpeg 9.0.1。20秒、2560×1440、60fpsのtestsrc2と48kHzサイン波を合成し、H.264とHEVCの入力を16 Mbpsで生成。出力はHEVC、30fps、目標6,635,520 bps、AAC 96 kbps、faststart。圧縮プロセスの壁時計時間を各3回測り中央値を比較した。アプリの事前解析・出力全体検証の時間は含まない。追加2回は速度優先を先に実行した。

| 入力 | 標準 | 速度優先 | 時間短縮 | SSIM 標準 → 速度優先 |
| --- | ---: | ---: | ---: | ---: |
| H.264 | 5.570秒 | 3.589秒 | 35.6% | 0.994536 → 0.992503 |
| HEVC | 5.572秒 | 3.599秒 | 35.4% | 0.994382 → 0.992151 |

速度優先は `-prio_speed 1` のみ追加し、目標ビットレートは変えない。初回の出力サイズはH.264入力で16,976,869 → 17,001,043 bytes、HEVC入力で16,997,754 → 17,005,941 bytesだった。SSIMは入力を30fpsへ変換して出力と比較した値で、高いほど元映像に近い。速度優先ではこの指標が下がっており、同一画質の高速化ではない。文字の可読性や実際の画面収録の品質を保証する結果ではない。

デコードのVideoToolbox支援とhardware framesも試したが、このサンプルでは約5.6〜5.7秒で改善せず、採用しなかった。Macの機種、解像度、映像内容、温度、電源設定によって結果は変わる。利用者の実データでの速度・画質確認は未完了。

## 実装と安全性

「標準」を既定のまま維持し、設定から任意に速度優先を選べる。投入時の設定をタスクごとに保持する。音声のみでは映像をコピーするため適用しない。未対応のVideoToolboxでは指定が無視される場合がある。詳細は[FFmpegのVideoToolbox実装](https://www.ffmpeg.org/doxygen/9.0/videotoolboxenc_8c_source.html)を参照。

成功出力の全体デコード検証と元ファイル変更検査は省略しない。統合テストで速度優先の実変換、HEVC出力、保持対象の音声パケット一致、全体検証後の置き換えを確認した。測定用動画はすべて合成データで、利用者の動画を変更していない。

ローカル測定スクリプトとJSON・ログは `.local-work/usage/benchmark.py`、`repeat-benchmark.py`、`benchmark/` に保存（Git対象外）。
