# 省容量モード：許可・操作・復旧のリリース前レビュー

2026-11-27。対象は一時的な外付け作業先を導入した実装と、通知・Musicの許可要求箇所。

## 判定

2026-11-28追記：ユーザーの指示により、物理ディスクの未実施事項をリリースノートに明記して0.2.1を公開する。以下の保留判定は11月27日時点の記録であり、実機確認が完了したことを意味しない。

**公開保留。** コード・自動テストの確認と、署名済みアプリに対してmacOSが実際に出す許可画面の確認は別である。利用者は現在外付けディスクを接続できないため、物理ディスクの許可・抜き差し確認は未実施。「どの環境でも不要な許可が一切出ない」「すべての状況で使いやすい」とは判定していない。

## 許可要求の経路

- 通常圧縮・起動時には外付けディスクの選択画面を自動表示しない。
- 容量不足の通知またはキューから選択画面を開く。候補の調査はボリュームの属性・容量・diskutilの情報取得であり、候補ディスクのファイル一覧取得や試験書き込みは行わない。ただし、実機TCCの画面が出ないことは未確認。
- 書き込み可否の試験は「このディスクを使う」を押した後。容量とタスクの状態を再確認してから、選んだ場所だけに一時ファイルを作る。満杯・識別不一致・削除済みタスクは試験書き込みの前に拒否する。
- フォルダ選択パネルは「別の場所を選ぶ」を押したときだけ表示。キャンセルで新しい作業先を登録しない。
- 通知の許可要求は設定画面の操作からだけ呼び出す。起動時の購読開始では要求しない。
- Musicの定期確認は `askPermission: false`。接続操作からだけ `true` を渡す。
- フルディスクアクセス・アクセシビリティ・画面収録の権限をこの機能のために要求する処理はない。
- OSが許可を記憶することと、アプリが作業先を永続保存することは別。作業先の設定・ブックマーク・履歴は追加しない。復旧に必要な一時記録だけを使用する。

Appleの説明では、Open/Saveパネル等でユーザーが選んだファイルへのアクセスは明示的な選択として扱われる。一方、そのような選択なしの保護されたファイルへの初回アクセスではOSが許可を求め、結果を記憶する。アプリの自作ボタンだけでOSの許可済み状態になるとは扱わない。

出典: https://developer.apple.com/documentation/bundleresources/information-property-list/nsremovablevolumesusagedescription

## 今回修正した問題

| 問題 | 修正 |
| --- | --- |
| 容量確認中に別の場所を選べ、必要容量が未確定のまま選択できる | 確認中は場所の変更・再確認・開始を無効化 |
| ディスク確認と試験書き込みがUIスレッドを止め得る | バックグラウンド実行し、進行中表示を維持 |
| 削除済み／再実行済みタスクでも成功のように画面を閉じる | 確認前後に状態を検証し、無効なら理由を表示。試験書き込み前に検査 |
| 別フォルダの検証失敗後に、以前の場所が選択されたまま | 新しい場所の検証開始時に選択を解除。選択したサブフォルダのパスも表示 |
| 外付けの必要容量を次の再試行で再度加算する | 外付けの見積もりを区別し、再試行で累積させない |
| 実空き容量が不明でも解放可能容量だけで使用可能と扱う | 解放可能容量だけでは候補として認めない |
| 復旧時に大きい原本を戻そうとして再び容量不足になり得る | 元の場所が空の場合、照合済みの小さい圧縮結果を戻す。結果が破損していれば退避原本へフォールバック |
| 1件の破損した復旧記録で他の復旧対象も表示できない | 読める記録を表示し、読めない記録と退避データは保持 |
| 試験書き込み失敗時に作成途中のファイルが残り得る | 排他的に作成し、書き込み失敗も含めて終了時に削除 |

## 検証範囲

実メディア処理を有効にした全119テスト成功（失敗・スキップなし）。そのうち省容量モードのテストは16件。アプリのコンパイル、全体のSwift整形チェック、日英381キーの一致と参照解決、差分の空白チェックも成功。

自動検証は容量不足・容量不明・削除後の容量減少、退避前／退避後／書き戻し後の障害、復旧先競合、候補破損、復旧記録の一部破損、再試行の容量見積もり、無効タスク、試験ファイルの削除、キューの単独実行、作業先の非永続化、別ボリューム（HFS+ディスクイメージ）へのコピーを含む。

署名済みアプリの実機確認として残る項目:

1. 未許可状態で候補画面を開いても不要なOSダイアログが出ないか。
2. 選択して使用した際の許可・拒否・再選択、次回起動時のOSによる許可保持。
3. 物理ディスクの切断／再接続、同名ディスク、マウント位置の変化。
4. ディスク選択画面の実操作・通知からの遷移・多数候補・狭い画面。
5. 正式な署名・公証済み配布物とSparkle更新の検証。

複数の容量不足タスクは、現状では各タスクについて作業先を選ぶ。後から投入した別ファイルまで暗黙に同じディスクへ退避しない。元の場所やマウント位置を移した場合の自動再探索は未対応。
