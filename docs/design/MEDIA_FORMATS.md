# 画像・音声対応の実装計画

2026-11-25。実装済み・配布済みの対応表ではない。0.1.0候補の検証、キュー／設定とLPの受け入れ後に、共通入力分類→画像→音声の順で実装する。既存の公開／実操作確認を省略するために形式追加へ置き換えない。

## 現在の制約

`InputFile.validate`はMOV/MP4/M4Vのみ。`MediaInfo.decode`はMOVコンテナーと映像1トラックを必須とする。`CompressionEngine`の容量見積り・検証も動画向けであり、拡張子を足すだけでは安全に拡張できない。

このMacでImage I/Oの読み書き型一覧を取得した記録は `.local-work/next/imageio-capabilities.json`。型一覧にあることは保持品質・圧縮率・最低対応OSの動作保証ではない。配布FFmpeg 9.0.1のエンコーダー一覧ではAAC/ALAC/FLAC/PCMを確認し、MP3エンコーダーはなかった。Homebrew版の能力を配布版の能力として扱わない。

## 共通の受け取りと保存

- 拡張子は候補絞り込みに使い、実データから種類・コンテナー・トラック／画像数を確認する。フォルダー・未取得のクラウドファイル・破損・不一致は理由を表示する。
- 左は「映像・画像」、中央は「自動」、右は「音声」。動画では従来の左=映像のみ、中央=映像と音声、右=音声のみを維持。画像は左と中央、音声単体は中央と右で処理する。対象外の領域に落としたファイルを別モードへ黙って読み替えない。
- 混在ドロップは各ファイルを分類し、適用対象だけ追加する。非対応件数と理由をまとめて表示し、対応ファイルまで一括拒否しない。分類中にメインスレッドを塞がず、同じ原本の重複処理を防ぐ。
- 種類・処理方式・設定をキュー投入時点で確定し保存する。既存履歴の種類未指定は動画として移行する。設定を変えても投入済み処理を変えない。
- 同形式で検証成功かつ小さくなった時のみ原本を置換する。失敗・停止後除外・削減なしは原本を保持。拡張子／形式を変える変換は別名出力とし、無設定での変換や原本削除をしない。
- 同一フォルダーへの一時出力、容量不足の具体的表示、原本変更検出、最終置換、通知、履歴は既存処理を共用する。映像・音声・画像の検証自体は分離する。
- 実行中は固定、停止は途中状態を保持、除外は停止後のみ、完了はキューから消す。画像も長い処理の停止が必要なため、Image I/Oの同期呼出をUIプロセスで行わない。署名済み補助プロセスと既存ProcessRunnerの停止／再開制御の接続を試作する。停止要求を完了後まで無視する実装を合格にしない。

## 画像の段階

| 形式 | 初期の処理方針 | 置換前の確認 |
| --- | --- | --- |
| JPEG | 同形式再圧縮。品質値はサンプル比較後に決定し、元の寸法を既定で維持 | EXIF向き1〜8、色プロファイル、寸法、全画素デコード、保持対象メタデータ。既に小さい画像は原本保持 |
| PNG | 可逆の同形式最適化。JPEG化・減色・透過削除を既定にしない | RGBA値、透過、色解釈、寸法、メタデータ。アニメーションを静止画化しない |
| HEIC/HEIF | JPEG/PNG後に同形式保持を評価。単なるJPEGへの変換で対応済みにしない | 複数画像、HDRゲインマップ、深度、向き、色・ビット深度。保持できない構成は理由付き非対応 |

Image I/Oの画像プロパティと付随データは別に扱う。付随データが失われても主画像が開けるだけでは合格にしない。GPSや撮影日等を圧縮の副作用として削除しない。プライバシー向け削除機能は別の明示設定として扱う。

[Appleの画像プロパティ](https://developer.apple.com/documentation/imageio/image-properties)、[付随データ取得](https://developer.apple.com/documentation/imageio/cgimagesourcecopyauxiliarydatainfoatindex(_:_:_:))、[書き出し設定](https://developer.apple.com/documentation/imageio/cgimagedestination)を調査元とする。APIの存在だけで往復保持を保証しない。

## 音声の段階

- 最初はM4A内AACの同形式再圧縮を試作する。映像なし・カバー画像ありを区別できる専用probeモデルを用意する。
- 元のチャンネル数・配置とサンプルレートを維持。既定でステレオをモノラル化しない。出力全体のデコード、時間・始端／終端、チャンネル、タグとカバー画像を検証する。
- WAV/AIFF/ALAC/FLACは可逆性を無設定で捨てない。可逆形式間の圧縮やAAC等への変換を別名出力の明示操作として設計し、同形式で削減できない場合は原本保持とする。
- MP3同形式再圧縮はエンコーダー選定・再配布条件・実バイナリの確認を独立した作業にする。MP3をAACに変えて元の拡張子で保存しない。
- 既定の音声ビットレートは単体音声で評価する。現行動画用96 kbpsを音楽にも無条件流用しない。会話／音楽・モノラル／ステレオで聴取し、品質と削減率を記録する。

## 受け入れ素材と条件

画像: 自作の文字・細線・グラデーション・写真相当のテクスチャ、透明境界、EXIF各向き、sRGB/Display P3、16bit PNG、アニメーションPNG、複数画像HEIFと付随データ付き構成。取得できない素材条件は未確認として残す。

音声: 自作音声・音楽相当の信号、左右異なるステレオ、無音区間、44.1/48 kHz、タグ／カバー画像、短い／長い素材、破損と可逆形式。信号の自動検査と聴取評価を区別する。

各段階で、混在一括投入・連続投入・重複原本・容量不足・原本外部変更・停止／再開／除外・スリープ復帰・削減なし・異常終了後の復旧を確認。キューのサムネイル／種類表示と日英の設定・失敗通知を含む。最低対応macOSでの能力確認と署名済み配布アプリでの検証後に対応形式を公開する。
