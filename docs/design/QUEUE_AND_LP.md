# キューUI・LP改修の実装仕様

2026-11-25。ユーザーの「検証が終わったらすぐにキューUIを見やすくし、LPも作り込む」という追加要望を具体化したもの。**実装・公開済みの仕様ではない。** 現行候補の検証→キュー／設定改修→新UIの実操作検証→実画面を使うLP改修の順で進める。画像・音声形式、ノッチの音楽・時計より先。

## 現状と変える理由

- QueueViewはタイトルの下に固定説明3行、カードごとにサムネイル・長い設定要約・状態・進捗・説明・操作を縦積みする。680×520の既定ウインドウで、動画の一覧より説明が目立つ。
- 空状態でも上部説明、中央の3領域説明、下部の置換条件が常設される。原本置換の条件は伝えつつ、同じ説明の反復を減らす。
- 成功カードは自動的に消えるが、下部の履歴消去ボタンは空状態で無効のまま残る。消去対象が何かを含めて履歴導線を見直す。
- 実行／停止／検証／失敗で操作条件が異なる。見た目の刷新でJobQueueの順序や安全条件を変えない。

## 共通の見た目

macOSのシステムフォント・SF Symbols・意味に基づく色を使用。アイコンのみは円形、文字付きの横長操作はピル型。主要操作は44pt程度の当たり判定を確保し、アイコン名ではなく操作名のツールチップとアクセシビリティラベルを付ける。キーボードのフォーカスが分かる状態にする。

Liquid Glassはツールバーや操作の層を中心とし、一覧の本文・エラー説明を多数のガラス面で覆わない。[Apple Materials](https://developer.apple.com/design/human-interface-guidelines/materials)と[Liquid Glass概要](https://developer.apple.com/documentation/TechnologyOverviews/liquid-glass)を参照。macOS 14〜25の代替表示、透明度を下げる／コントラストを上げる設定でも情報階層を保つ。

ui-ux-pro-maxの検索結果から遅延生成する一覧、意味のある操作部品、ラベルとフォーカス、コントラストの方針を採用する。Web向けの動画背景・Interへの変更・根拠未確認の利用率向上の数値は採用しない。アプリにはシステムフォント、LPには既存Lunamo系の書体と色を優先する。

## キューの構成

1. 上部: 「圧縮キュー」、処理中／一時停止／待機の件数、追加（丸い＋）、設定（丸い歯車）。件数に失敗がある場合は見落とさない表示を加える。
2. 実行方式: 自動／直列／並列の選択を一か所に保持。「自動」の実際の上限と一時停止による枠保持はヘルプで確認できる。停止中の枠保持が待機の原因なら、その理由は一覧内にも表示する。
3. 本文: 実行中の項目を先頭に固定し、その後は並べ替え可能な項目を既存の順序で表示。停止・失敗を別グループへ勝手に並べ替えない。実行中とそれ以外の境界は余白または区切りで示す。
4. 行: 左に実サムネイル、中央にファイル名（最大2行）と短い圧縮対象、右に状態と今できる操作。設定の全要約は詳細へ。ファイル名全体はヘルプ／アクセシビリティで読める。進捗バーと百分率は同じ行の下部にまとめる。
5. 容量: 実際に取得できた入力サイズを表示し、未取得なら取得できていないと分かる表示にする。UI表示のために動画を再解析したり、クラウドのファイルを自動ダウンロードしない。出力の容量や残り時間を推測して実測のように表示しない。
6. 結果: 成功／削減なしはカードを消し、短い完了要約に件数と前後サイズ、原本保持件数を示す。失敗は理由と対処を残す。以前の完了をキューへ戻さず、履歴へ進む導線が必要か試作で判断する。
7. 空状態: 追加ボタンとノッチ3領域の意味を短く案内。常設説明は減らすが、原本を置き換える条件は初回でも分かる場所に残す。

### 状態と操作（実装の判断基準はJobQueue）

| 状態 | 表示の主情報 | 操作・制約 |
|---|---|---|
| 解析中・圧縮中・検証中 | 状態、取得できる進捗 | 先頭固定。個別一時停止。並べ替え・除外不可。検証中を圧縮100%と同一視しない |
| 一時停止 | 停止中、再開位置、枠保持による待機理由 | 再開／除外。勝手に消さない。順序は既存仕様と本人の並べ替えを尊重 |
| 停止処理中・除外処理中 | 処理終了待ち | 操作連打・二重実行を防ぐ。子プロセス終了前に枠を解放しない |
| 待機 | ファイル名、待ち順、圧縮対象 | ドラッグ並べ替え／除外。優先度の別設定は作らない |
| 失敗・中断 | 利用者向け理由、次の操作 | 再試行／除外。容量不足は空き・必要・不足量とフォルダーを開く導線を省略しない |
| 完了・削減なし | 一時的な前後サイズ要約 | 個々の完了と同時にキューから消す。削減なしは原本保持と明示 |

全体停止は復活させない。canReorder／canRemove／runningIDs／pausedIDsを使用し、View側に別の状態判定表を重複実装しない。設定変更を投入済みタスクへ遡って適用しない。

## 設定・エラーの整理

- 圧縮: 映像の強度／fps／速度、音声のビットレートを区別する。映像のみ・音声のみ・両方で何に効く設定かを、詳細を開かなくても分かるようにする。
- 常駐と操作: ログイン起動、ショートカット、通知。OS側の許可が不足していれば、設定済みのように見せず理由と設定先を案内する。
- 更新と診断: バージョン・更新状態・診断。設定シートを開いてもSparkleの再起動を妨げない既存修正を保つ。
- 数式やログは開閉式の詳細へ。容量不足・元ファイル変更など行動に必要な理由を、技術詳細に隠さない。

## LPの構成と素材

既存site/style.cssの淡いグリーン、Avenir Next／システム書体、余白、日英別ページ、外観切替を継承。site/licenses/Lunamo-template-MIT.txtを維持する。

| 順序 | 訪問者に伝える内容 | 必要な素材・根拠 |
|---|---|---|
| 1 | 何をするアプリか、Macに入れられるか | 短い用途説明、対応OS／Apple Silicon／動画形式、公開版のDL |
| 2 | ノッチへドラッグして対象を選ぶ | 3領域を見せる実操作デモ。説明図と録画を区別 |
| 3 | 複数投入後の扱い | 新キューの実画面。順番変更、停止／再開、待機理由 |
| 4 | 元ファイルと容量の扱い | 検証＋削減成功時だけ置換、削減なし・失敗時の保持。実測の前後サイズと測定条件 |
| 5 | 圧縮の選択と制約 | 標準もハードウェア使用、速度／画質／容量の関係。設定不要で使える範囲を正確に説明 |
| 6 | 導入・更新・よくある質問 | 公証済みDMG、Applicationsへ移動、Sparkle更新、日英DMGは同じアプリ |

必要素材は、空キュー・複数待機・実行中＋停止中・容量不足・ノッチ展開の実スクリーンショット、短いノッチ投入デモ。テスト用ファイル名を使用し、個人の履歴や他アプリの内容を入れない。新UIが配布版にまだ入っていない間は、新UIの画像を現在の配布物として訴求しない。

動画は勝手に音を再生せず、静止ポスターと再生操作を用意。動きを減らす設定では静止画でも内容が分かる。架空の口コミ・ユーザー数・一般化した性能向上率は追加しない。現時点の合成素材の結果は条件付きの検証値としてだけ扱う。

## 実装の順序と受け入れ条件

### A. キュー／設定UI — [Issue #34](https://github.com/mani1261790/NotchCompressor/issues/34)

- 既定680×520、最小540×380、大きいウインドウで、空・1件・多数・長い日英名を確認。
- 圧縮中、検証中、一時停止、失敗、容量不足、削減なしで、主情報と操作が隠れない。
- 追加→待ち順変更→個別停止→途中再開→停止後除外→再試行→完了除外を実操作。バックグラウンド継続と更新延期も維持。
- 日本語／英語、明暗、透明度を下げる設定、キーボードとVoiceOverのラベル・順序を確認。
- 自動試験では既存Scheduling／Pause／Feedback／Localizationの契約を維持。視覚評価は別に記録し、自動試験だけで完成としない。

### B. LP — [Issue #35](https://github.com/mani1261790/NotchCompressor/issues/35)

- Aの実画面を取得し、画像に対応する配布版が利用できる状態で公開する。
- ja/en、320／375／768／1440px、明暗、キーボード、動きを減らす設定を実表示で確認。
- 無操作で大きな動画を取得しない。画像寸法を固定してレイアウトのずれを避け、読み込みを計測する。
- 言語切替→対応するDMGのダウンロード→署名済み配布物との照合まで確認。更新フィードとの版ずれを残さない。
- 現行release/0.1.0-siteの配布リンク更新と、ここでのLP再設計は別の成果物として扱う。

関連: docs/NEXT_STEPS.md、docs/RELEASE_0_1_0.md。未確認の現行版の項目を、この設計文書の作成によって完了扱いにはしない。

## 実装進捗（2026-11-25・第一段階）

- ユーザーの追加要望「シンプルでわかりやすい画面」「並べ替えのgrabカーソル」「設定も改善」を反映して着手。
- キュー上部の常設説明を情報ボタンのポップオーバーへ移動。一時停止・スリープによる待機理由は常設表示を維持。圧縮対象は短く表示し、投入時の詳細設定を開閉式にした。進捗率はバーと同じ行へ。
- 並べ替え可能な行にのみopenHandカーソルを適用。行から離れる／実行開始で再生成される／除外される際にカーソルを解放する。既存のcanReorder・ドロップ処理は維持。グリップと固定ピンをアイコンに整理。
- 設定を「圧縮」「一般」「更新とサポート」の3分類へ分割。実際の設定値や更新・ログイン・通知の処理は変更しない。
- ビルドと言語キー検査は成功。実表示・手のカーソルと操作ボタンの競合・狭い画面での配置・日英の最終受け入れは未実施。配布用アプリの差替や公開はまだ行っていない。

### 実表示の初回確認

ローカルreleaseビルドをDeveloper ID署名して起動。英語で空キュー、設定の圧縮／一般／更新とサポートの切替と内容を実表示で確認。設定値は変更せず、終了後に/Applicationsのビルド10へ戻した。汎用build-app.shのad-hoc成果物ではSparkleとのTeam ID不一致で起動終了したため、検証用バンドル全体を既存Developer IDで再署名した（配布候補ビルド10は変更なし）。

初回の実表示では分類ラベルが2行になること、圧縮の補足が主要設定を押し下げることを確認したため、分類ラベルを非表示にし、ビットレートの補足と計算式を同じ開閉項目へ移動。変更後の再ビルド・翻訳検査は成功。今回の最終配置、非空キューとカーソル、日英両方の画面確認は引き続き必要。既存のScheduling/Pause/Localization計20テストは改修第一段階で全件成功。

### 非空キューの実操作確認

行を「グリップ／サムネイル／ファイル名・圧縮対象・状態」と右側の操作にまとめ、Finder表示は詳細内へ移動。手のカーソルの対象をファイル情報領域に限定し、状態変更時も解除する。合成素材のコピー3件（各430.3 MB）を新しい署名済みローカルビルドに追加し、以下を実画面で確認した。

- 1件実行・2件待機。実行中はピンと停止ボタンを表示し、除外は表示しない。
- 2%で個別停止し、停止1件・待機2件を保持。停止後に再開／除外を表示。
- 待機2件をそれぞれ除外し、停止中の1件は残る。
- 再開で進捗が増加。7%で再停止・除外し、終了処理中はボタン無効。その後空キューへ戻る。
- 検証コピー3件のSHA-256がすべて投入前と一致。検証版を終了し、インストール済みビルド10へ復帰。

CUAの行・グリップからのドラッグでは順序変更もQueueReorderのイベントも確認できなかった。新UIのドラッグ成立とgrabカーソルの目視は未確認であり、成功扱いにしない。スクリーンショットで長い進捗説明がバーを圧迫していたため、進捗ラベルを百分率だけに変更（検証フェーズには既存の別状態表示がある）。最終の百分率表示・日英・最小サイズは引き続き確認する。
